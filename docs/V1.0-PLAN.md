# Completion roadmap to v1.0

Current scope entry point: [COMPLETION-REGISTER.md](COMPLETION-REGISTER.md). It preserves the approved table and every campaign item with partial evidence and remaining acceptance. This document also retains historical planning/evidence.

Approved in the project conversation on 2 October 2026. This sequence supersedes
the older release numbering in NEXT-UPDATES.md; it does not remove its 180 items,
the comparison audit, earlier requests or necessary supporting work.

The v0.41 preview implements the first [depth and replayability pass](releases/V0.41-COVERAGE.md).
Remaining authored pools, consequence links, ownership systems and mode work
stay open; counts of new scenes do not by themselves close campaign requirements.

v1.0 means the complete agreed base game. Known missing accepted mechanics are
not postponed as maintenance. Later maintenance addresses newly discovered
problems; later content updates expand an already complete base game. Dates and
version numbers do not override acceptance. This is a milestone plan, not a
claim that the entire scope is implemented or that a game can be proven bug-free.

Usability, accessibility, balance, save compatibility and performance belong in
every milestone. The later phases broaden verification; they do not defer basic
quality. Patch releases can fix a milestone; adjacent milestones can be combined
when ready. It is not necessary to invent every intermediate decimal release.

## Combined milestone delivery

At the user's request, v0.33–v0.40 are delivered together as **v0.40 Connected
Lives**, rather than eight separate packages. [Coverage](releases/V0.40-COVERAGE.md)
states the implemented behaviour, exact limits and remaining integration work.
This changes release packaging, not the full accepted scope. v0.41–v0.49 must
reconcile the complete campaign, expand remaining depth and resolve omissions
before the feature-complete checkpoint. Version 1.0 still requires that work.

## Traceability and acceptance

Maintain request → planned milestone → implementation → verification → delivered
artifact. Distinguish planned, in progress, implemented, verified and delivered.
The ongoing register and per-release coverage documents provide the audit trail.
Partial foundations do not close full requests. Every delivered feature must be
reachable with clear requirements/costs, produce useful decisions or information,
survive saves/transfers where applicable, avoid contradictory or duplicate
outcomes, fit the dark accessible interface and pass relevant checks.

Newly discovered necessary work belongs before v1.0. Assess genuinely new large
expansions separately; accepted base-game work is not silently moved after v1.0.
No finite test suite proves every possible life or establishes superiority to
another game. Completion requires the coverage audit and representative play,
not just counts of features or green automated checks.
